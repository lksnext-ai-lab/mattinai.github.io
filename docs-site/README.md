# Mattin AI — Documentation Site

Public product documentation for [Mattin AI](https://github.com/lksnext-ai-lab/ai-core-tools), built with [Fumadocs](https://fumadocs.dev) on Next.js and exported as a **static site** (`output: 'export'`).

Lives under `docs-site/` in the repository.

---

## Relationship to `docs/`

The repository contains two separate documentation layers:

| Layer | Location | Audience |
|---|---|---|
| Internal / contributor docs | `docs/` (repo root) | Developers working on the codebase |
| Public product site (this) | `docs-site/` | End users and API consumers |

The `docs/` tree is the source material used to author `docs-site/` content — it is **not** served or migrated. See `CONTENT-SOURCES.md` for the mapping.

---

## Prerequisites

- Node.js 18 or later (LTS recommended)
- npm (bundled with Node.js)

---

## Local development

```bash
cd docs-site
npm install
npm run dev
```

Opens the Next.js dev server at http://localhost:3000.

The `predev` hook runs `scripts/generate-openapi-docs.mjs` automatically before the server starts, so the API reference pages are always regenerated from the committed `api-reference/openapi.json`.

---

## Build (static export)

```bash
npm run build
```

Produces the static site in `out/`. The `prebuild` hook runs the same OpenAPI page generator before the Next.js build.

To preview the built output locally:

```bash
npm run start
```

This serves `out/` using the `serve` package (configured in `package.json`).

## API reference

### How the pages are generated

The per-operation MDX pages under `content/docs/api-reference/` are generated by `scripts/generate-openapi-docs.mjs`, which uses `fumadocs-openapi` to read `api-reference/openapi.json` and write one MDX file per operation. This script runs automatically on `predev` and `prebuild`.

The generated files include a comment banner (`addGeneratedComment: true`) — **do not hand-edit them**; they will be overwritten on the next build.

`content/docs/api-reference/meta.json` is **hand-maintained** (the generator runs with `meta: false`). When new endpoints are added to the backend and the snapshot is regenerated, the new page names must also be appended to `meta.json` to appear in the sidebar.

### Refreshing the OpenAPI snapshot

The committed `api-reference/openapi.json` is a snapshot of the public API (`/public/v1` paths). To regenerate it from the live backend code, run from the **repo root** with the backend Python dependencies installed:

```bash
python docs-site/scripts/export-openapi.py
```

**Why not use `/openapi-public.json` directly?** The backend's `/openapi-public.json` endpoint returns an empty spec under the current FastAPI version due to lazy router inclusion. The script works around this by using FastAPI's `TestClient` to build the ASGI stack (resolving all lazy includes) and fetching the full `/openapi.json`, then filtering to `/public/v1` paths and trimming schemas to those reachable from the public paths.

**Fallback (no backend deps installed):**

```bash
# Start the backend, capture the full spec, then filter it:
curl -s http://localhost:8000/openapi.json -o /tmp/full-openapi.json
python docs-site/scripts/export-openapi.py --from-file /tmp/full-openapi.json
```

After regenerating, commit `api-reference/openapi.json` and note the path count and date in the commit message.

## Deployment

`npm run build` produces a fully static site in `out/`, which can be served from any static hosting platform (e.g. GitHub Pages, Netlify, a plain web server).

The site is intended to be deployed from another Mattin AI repository; this repository does not define deployment CI — the consuming repo owns that.

**Sub-path deployment:** if the site is served under a sub-path (e.g. GitHub project Pages at `/<repo>/`), set `basePath` and `assetPrefix` in `next.config.mjs` before building:

```js
const config = {
  output: 'export',
  reactStrictMode: true,
  basePath: '/<repo>',
  assetPrefix: '/<repo>',
};
```

Rebuild after changing these values. Do not set them when serving from the domain root.
